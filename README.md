A Spring Boot REST API for managing nurse data. This project is part of the **M0492 - Introduction to Back End** module and extends the previous exercise by connecting the application to a MySQL database through Spring Data JPA and Hibernate.

## Activity overview

The activity involves designing the data model in MySQL Workbench, generating and checking the schema with Hibernate, and adapting the endpoints to query the database. It also includes testing the application with both a local and a centralized database, and documenting the team's tests with Postman.

## Current status

- The `Nurse` entity is mapped to the `nurse` table.
- Spring Data JPA provides the nurse repository.
- The current configuration points to a local MySQL database named `hospital`.
- Hibernate is configured with `ddl-auto=update` to update the schema from the entities.
- The nurse listing endpoint (`GET /nurse/index`) queries the repository.
- Login and search by name still need to be implemented in the controller.
- The connection to a centralized MySQL server and the Postman test documentation must be configured and verified for submission.

## Data model

The `Nurse` entity defines the `nurse` table with the following fields:

| Field | Java type | Constraints |
| --- | --- | --- |
| `idNurse` | `Integer` | Auto-generated primary key |
| `username` | `String` | Unique |
| `password` | `String` | — |
| `name` | `String` | — |
| `surname` | `String` | — |
| `email` | `String` | — |

The final logical design should be created in MySQL Workbench and compared with the schema generated by Hibernate. `ddl-auto=update` helps update the schema during development, but does not replace designing or verifying the database.

## Database configuration

By default, the application attempts to connect to `jdbc:mysql://localhost:3306/hospital` using the `root` user with no password. Create the `hospital` database on your MySQL server or adjust the configuration for your environment.

To avoid storing credentials in the repository, you can override the configuration with environment variables. For example, in PowerShell:

```powershell
$env:SPRING_DATASOURCE_URL = "jdbc:mysql://localhost:3306/hospital"
$env:SPRING_DATASOURCE_USERNAME = "root"
$env:SPRING_DATASOURCE_PASSWORD = "your_password"
```

To use a centralized database, set the same variables to the URL, username, and password provided by the database host. Do not publish credentials in source code, the repository, or Postman screenshots.

## Running the application

Clone the repository and navigate to the project directory:

```bash
git clone https://github.com/Akashdeep-Kallon/M0492-Introducci-al-Back-End.git
cd M0492-Introducci-al-Back-End
```

On Windows, start the application with the Maven wrapper:

```powershell
.\mvnw.cmd spring-boot:run
```

On macOS or Linux:

```bash
./mvnw spring-boot:run
```

The API will be available at `http://localhost:8080`, provided the MySQL connection is configured correctly.

## API endpoints

| Method | Endpoint | Description | Status |
| --- | --- | --- | --- |
| `GET` | `/nurse/index` | Returns the list of nurses from the database. | Implemented |
| `POST` | `/nurse/login` | Validates a nurse's credentials. | Pending |
| `GET` | `/nurse/name/{name}` | Searches for a nurse by name. | Pending |

The expected login request body uses fields from the `Nurse` entity:

```json
{
  "username": "nurse01",
  "password": "password123"
}
```

The behavior and responses of the pending endpoints should be tested with Postman once they are implemented.
